```
                  └────────────────────────┘
```

## ⚡ 1. Команды запуска и сценарии верификации

### 1.1. Запуск Unit и Integration тестов (Vitest)
```bash
npm test
```
Запускает все 5 тестовых сьютов (`56 passed`):
- `tests/core/graph.test.ts` — 10 тестов: детекция циклов, проверка граней, топологические ярусы глубины, валидатор переходов FSM.
- `tests/core/scheduler.test.ts` — 9 комплексных тестов: исполнение цепочек, вееров, параллелизм, каскад блокировок.
- `tests/core/parser.test.ts` — 23 теста: детерминированный разбор синтаксиса целей, регулярных выражений, связей и команд `start:`.
- `tests/storage/storage.test.ts` — 5 тестов: контракты SQLite и Memory адаптеров, сохранение связей, каскадное удаление.
- `tests/server/api.test.ts` — 9 тестов: интеграция Express-роутера с Supertest, валидация Zod, корректность кодов 200, 400, 404.

### 1.2. Запуск сквозных E2E тестов (Playwright)
```bash
npm run test:e2e
```
Запускает браузер Chromium в headless-режиме (`kanban-module/tests/e2e/kanban.spec.ts`):
- Загрузка страницы песочницы;
- Создание новой задачи через модальное окно;
- Проверка перетаскивания (Drag & Drop) карточки между колонками;
- Переключение на интерактивную вкладку графа зависимостей (SVG-холст);
- Проверка всплывающих уведомлений (Toasts) и переключения языка интерфейса.

### 1.3. Статический анализ типов (Typecheck / Lint)
```bash
npm run lint
```
Выполняет проверку TypeScript компилятором без генерации JS-файлов (`tsc --noEmit`). В проекте действует строгое правило **0 предупреждений и 0 ошибок компиляции**.

### 1.4. Продакшн-сборка приложения
```bash
npm run build
```
Компилирует фронтенд через Vite в директорию `/dist`.

## 🔍 2. Разбор ключевых тест-кейсов шедулера

В файле `kanban-module/tests/core/scheduler.test.ts` реализованы строгие поведенческие спецификации:

| Тест-кейс | Сценарий графа | Проверяемый инвариант |
|---|---|---|
| **Кейс 2: Строгая цепочка** | $1 \to 2 \to 3$ | Задачи выполняются строго последовательно: задача 2 стартует только после перехода задачи 1 в `done`, задача 3 — после 2. |
| **Кейс 3: Веер зависимостей** | $1 \to 2$, $1 \to 3$, $1 \to 4$ | После завершения задачи 1 задачи 2, 3 и 4 стартуют одновременно (с учетом пула `maxParallel`). |
| **Кейс 4: Сходящийся узел** | $1 \to 3$, $2 \to 3$ | Задача 3 ждет завершения **обоих** предков. Если завершилась только задача 1, задача 3 остается в ожидании. |
| **Кейс 5: Лимит параллелизма** | $1, 2, 3, 4, 5$ при `maxParallel = 2` | В любой момент времени в статусе `in_progress` находится не более 2 задач. |
| **Кейс 6: Каскадный сбой** | $1 \to 2 \to 3$, задача 2 падает (`failed`) | Задача 3 автоматически переводится в `blocked`. При вызове `retry` для задачи 2 задача 3 возвращается в `ready`. |
| **Кейс 8: Приоритизация очереди** | Задачи $A$ (`prio: 1`), $B$ (`prio: 10`) | Шедулер всегда выбирает задачу с максимальным приоритетом при освобождении слота. |

## 🛠️ 3. Повседневные рабочие процессы разработчика

### Локальный запуск Full-Stack песочницы:
```bash
npm run dev
```
Сервер стартует на порту `3000` (`http://localhost:3000`). Изменения в коде фронтенда мгновенно обновляются, серверные роуты и база данных SQLite готовы к работе.

### Инспекция базы данных SQLite:
База данных располагается в корне проекта: `kanban-data.db`. Для проверки содержимого таблиц:
```bash
sqlite3 kanban-data.db "SELECT id, title, status, depends_on FROM kanban_tasks;"
```

### Диагностика SSE потока событий в браузере:
1. Откройте Chrome DevTools (F12) → вкладка **Network**.
2. Установите фильтр: `events`.
3. Кликните на запрос `GET /api/kanban/events` → откройте вкладку **EventStream**.
4. В реальном времени наблюдайте за поступлением событий `task:log`, `task:progress` и `task:updated`.
