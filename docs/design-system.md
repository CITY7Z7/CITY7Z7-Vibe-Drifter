# 🎨 Дизайн-система: CITY7Z7-Vibe-Drifter (design-system.md)

> **Спецификация визуального языка, дизайн-токенов, интерактивных состояний и руководство по модификации внешнего вида.**

---

## 🧭 Философия визуального интерфейса

Дизайн-система **CITY7Z7-Vibe-Drifter** спроектирована по канонам современных операционных центров управления и сред разработки (Mission Control / IDE-grade interface):

1. **Высокая информационная плотность (High Information Density):** Минимальные пустые поля, компактные отступы, максимальное пространство для карточек задач, графа зависимостей и логов выполнения.
2. **Нулевой джиттер (Zero Jitter Layout):** Фиксированная сетка колонок, виртуализация списков при необходимости, плавные CSS-переходы без рывков ширины карточек.
3. **Строгая изоляция (Zero Style Bleed):** Модуль не переопределяет глобальные стили `body`, `html` или селектор `*`. Все правила замкнуты внутри контейнера `.kb-orchestrator-root` с префиксами классов `kb-*`.
4. **Контрастная семантическая дифференциация:** Каждый статус жизненного цикла, тип связи в графе и уровень критичности ошибки имеет свой неповторимый цветовой маркер, различимый даже периферийным зрением.

## 🎨 Семантическая палитра статусов (Status Palette)

Жизненный цикл задачи состоит из 7 строгих состояний. Каждому состоянию соответствует закрепленный цветовой акцент:

| Статус | Цвет акцента | Tailwind-токен границы | Tailwind-токен фона | Индикатор | Смысловое назначение |
|---|---|---|---|---|---|
| `backlog` | Нейтральный сланец | `border-slate-600` | `bg-slate-900/60` | `bg-slate-400` | Задача запланирована, ожидает перевода в работу |
| `ready` | Теплый янтарь | `border-amber-600` | `bg-slate-900/60` | `bg-amber-400` | Готова к исполнению, ожидает слот шедулера |
| `in_progress` | Электрический синий | `border-blue-600` | `bg-slate-900/60` | `bg-blue-400` ⚡ | Активно исполняется воркером (`TaskExecutor`) |
| `review` | Королевский пурпур | `border-purple-600` | `bg-slate-900/60` | `bg-purple-400` 👁️ | Требует ручного подтверждения человеком |
| `done` | Изумрудный зеленый | `border-emerald-600` | `bg-slate-900/60` | `bg-emerald-400` ✓ | Завершена успешно, разблокирует зависимых потомков |
| `failed` | Алый рубин | `border-rose-600` | `bg-slate-900/60` | `bg-rose-400` ✗ | Завершилась ошибкой, исчерпала лимит попыток |
| `blocked` | Огненный оранжевый | `border-orange-600` | `bg-slate-900/60` | `bg-orange-400` 🚫 | Заблокирована из-за сбоя в зависимостях |

## 🔮 Интерактивная подсветка связей (Pedigree Highlighting)

При наведении курсора на любую карточку задачи или узел на графе активируется алгоритм поиска предков и потомков:

```
           [ Задача А (Предок) ]  <─── Оранжево-янтарная подсветка (Ancestors)
                     │
                     ▼
           [ Задача Б (Фокус) ]   <─── Синее свечение ring-2 ring-blue-500 (Active)
                     │
                     ▼
           [ Задача В (Потомок) ] <─── Бирюзовая подсветка (Descendants)
```

- **Активная карточка (`isHovered`):**
  Классы: `ring-2 ring-blue-500 border-blue-400 bg-slate-800 shadow-lg shadow-blue-500/10`
- **Прямые и транзитивные предки (`isAncestorOfHovered`):**
  Классы: `border-amber-500/80 bg-amber-950/20 ring-1 ring-amber-500/50`
  *Смысл:* показывает, от каких именно задач зависит текущая карточка.
- **Прямые и транзитивные потомки (`isDescendantOfHovered`):**
  Классы: `border-cyan-500/80 bg-cyan-950/20 ring-1 ring-cyan-500/50`
  *Смысл:* показывает, какие задачи ждут выполнения текущей.

## 🌓 Темы оформления: Темная (Dark) и Светлая (Light)

Система поддерживает динамическое переключение тем через состояние компонента `<KanbanBoard initialTheme="dark" />` или проп `theme`.

```css
/* Базовые цвета тем */
.kb-orchestrator-root[style*="colorScheme: dark"] {
  --kb-bg-canvas: #020617; /* slate-950 */
  --kb-bg-surface: #0f172a; /* slate-900 */
  --kb-bg-card: #1e293b; /* slate-800 */
  --kb-text-main: #f8fafc; /* slate-50 */
  --kb-text-muted: #94a3b8; /* slate-400 */
  --kb-border-dim: #334155; /* slate-700 */
}

.kb-orchestrator-root[style*="colorScheme: light"] {
  --kb-bg-canvas: #f8fafc; /* slate-50 */
  --kb-bg-surface: #ffffff; /* white */
  --kb-bg-card: #f1f5f9; /* slate-100 */
  --kb-text-main: #0f172a; /* slate-900 */
  --kb-text-muted: #64748b; /* slate-500 */
  --kb-border-dim: #cbd5e1; /* slate-300 */
}
```

## 📐 Типографика и мерная сетка

- **Основной шрифт (UI Body):** Нативная системная гротескная гарнитура (`font-sans`: Inter, -apple-system, BlinkMacSystemFont, Segoe UI, Roboto).
- **Моноширинный шрифт (IDs, Метрики, Логи, Код):** JetBrains Mono, Fira Code, Menlo, Monaco (`font-mono`).
- **Иерархия размеров:**
  - `text-[10px]`: Служебные бейджи, счетчики попыток, статус подключения SSE.
  - `text-xs` (12px): Текст карточек, метаданные, кнопки действий.
  - `text-sm` (14px): Заголовки карточек, элементы меню.
  - `text-base` (16px): Заголовки модальных окон, табы.
  - `text-lg` / `text-xl`: Название доски, акцентные заголовки.
- **Скругления (Border Radius):**
  - Кнопки и инпуты: `rounded-lg` (8px).
  - Карточки задач: `rounded-xl` (12px).
  - Бейджи и теги: `rounded-md` (6px) или `rounded-full` (индикаторы статуса).

## 🧩 Анатомия компонентов

### 1. Карточка задачи (`<TaskCard />`)
```
┌────────────────────────────────────────────────────────┐
│ #task-42  ⚡ shell                     [prio: 5] [×3]  │ ◄── Header & Badges
├────────────────────────────────────────────────────────┤
│ Сборка фронтенд-бандла Vite и компиляция TypeScript   │ ◄── Title
├────────────────────────────────────────────────────────┤
│ ⏳ Ждёт: #task-39 (тесты), #task-40 (миграции)         │ ◄── Dependency warning
├────────────────────────────────────────────────────────┤
│ [████████████████████░░░░░░░░░░] 68%                  │ ◄── Realtime Progress
├────────────────────────────────────────────────────────┤
│ [frontend] [build] [ci]         [▶ Старт] [✕ Отмена]  │ ◄── Labels & Actions
└────────────────────────────────────────────────────────┘
```

### 2. Колонка Канбан (`<Column />`)
- Фиксированная ширина (`min-w-[280px] max-w-[320px]` на десктопе, горизонтальный скролл на мобильных).
- Заголовок с точкой статуса и бейджем количества задач.
- Для колонок `Failed` и `Blocked` предусмотрена кнопка сворачивания/разворачивания (`collapsible`), экономящая горизонтальное пространство при отсутствии инцидентов.
- Подсветка зоны Drag & Drop: при перетаскивании карточки колонка меняет фон на `bg-blue-500/10 border-blue-500/50`.

### 3. Интерактивный SVG-граф (`<DependencyGraph />`)
- **Узлы (Nodes):** Прямоугольники с карточками задач, позиционируемые по колонкам глубины (`depth` от 0 до N).
- **Связи (Edges):** Кубические кривые Безье со стрелками `marker-end="url(#arrow-status)"`. Цвет линии наследует цвет статуса родительского узла.
- **Инструменты холста:** Кнопки масштабирования (+ / -), центрирования графа и полноэкранного режима.

### 4. Терминал логов задачи (`<TaskDetailModal />`)
- Темное окно в стиле xterm / VS Code Terminal (`bg-black text-emerald-400 font-mono text-xs`).
- Автоматический скролл вниз при поступлении новых строк лога через SSE.
- Вкладка визуального редактора зависимостей: добавление и удаление связей в один клик.

## 🛠️ Инструкция: Как изменить дизайн проекта

### Сценарий 1. Изменение цветовой палитры статусов
Если вам необходимо изменить цвет статуса (например, сделать `review` оранжевым, а `blocked` серым):
1. Откройте файл `kanban-module/src/ui/Column.tsx`.
2. Найдите объект конфигурации `statusHeaderColors`:
   ```ts
   // Измените Tailwind-классы для нужного статуса:
   const statusHeaderColors: Record<TaskStatus, { border: string; dot: string; bg: string }> = {
     // ...
     review: { border: 'border-amber-600', dot: 'bg-amber-400', bg: 'bg-slate-900/60' },
   };
   ```
3. Соответствующие бейджи обновите в `kanban-module/src/ui/TaskCard.tsx` в функции `getStatusBadgeClass`.

### Сценарий 2. Настройка темы под корпоративный бренд хост-приложения
Если проект внедряется в систему со светлой темой или фирменными цветами:
1. Передайте начальные свойства в компонент:
   ```tsx
   <KanbanBoard
     apiBase="/api/kanban"
     initialTheme="light"
     className="border-none shadow-none"
   />
   ```
2. Для глубокой кастомизации фона переопределите CSS-переменные в вашем глобальном стилизованном блоке:
   ```css
   .kb-orchestrator-root {
     --brand-primary: #4f46e5; /* Indigo */
   }
   ```

### Сценарий 3. Замена иконок или добавление новых элементов
Интерфейс использует оптимизированные inline SVG и легковесные символы Unicode, что гарантирует работу без внешних зависимостей шрифтов. При желании использовать библиотеку `lucide-react`:
1. Импортируйте нужные иконки в компонент карточки:
   ```tsx
   import { Play, Pause, RotateCcw, Check, X } from 'lucide-react';
   ```
2. Замените текстовые кнопки на `<Play className="w-3.5 h-3.5" />`.
